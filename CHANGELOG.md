# Whisker Hunt changelog

## v1.9 — Cat-target-aware best-frame selection
- The live camera now evaluates the area **you tapped as the cat target**, not just overall background sharpness, when choosing a still after a successful throw.
- Reassesses up to eight buffered frames against the **latest** target position at the moment of capture; moving the target changes which still wins.
- Uses 75% focus-region quality and 25% full-photo quality, with a penalty for badly exposed target areas. This is a simple offline image-detail heuristic, **not** cat recognition.
- Displays a brief "Selecting the clearest frame" message during processing and reports both focus-area and whole-photo quality.
- Adds a current-frame fallback if the rolling buffer is unexpectedly empty; checks session identity before applying asynchronous results so a closed/restarted camera cannot overwrite the photo.
- CatDex photos, sightings, XP, quests, native snapshot schema and backup/restore format are unchanged.
- Updates Android display version to 1.9.0 (version code 19) and the offline web asset cache to v19.


## v1.8 — Live encounter (experimental)

- Added **Live encounter** to the Catch menu. When browser/WebView camera access is supported, the real camera preview appears **behind the right-side Whisker Pod / Dangle Lure dock**, so you drag while looking at the scene rather than after taking a photo.
- Added an **in-memory rolling buffer** of at most eight JPEG stills, sampled approximately every 450 ms and kept for up to three seconds. The app scores exposure and whole-frame detail locally and chooses the strongest recent still when the Whisker Pod lands. **No video recording, microphone, upload, or cloud recognition.**
- Added Android WebView camera-permission handling based on MAUI's `MauiWebChromeClient` API: request Android camera permission first; grant **video only** to the app's bundled local UI, never microphone or arbitrary web pages. This native code **has not been compiled or device-tested here**.
- Added clear camera-unavailable/permission-denied fallback to the existing native photo picker or gallery. The ordinary still-photo encounter remains available.
- Fixed retake/replace while live: freeze a usable still **before** opening the picker, so cancelling the picker doesn't leave a blank preview.
- Stop camera tracks on capture, modal close, navigation, retake, and backgrounding; keep the CatDex untouched until the user explicitly saves.
- Updated Android `ApplicationDisplayVersion` to `1.8.0` and monotonically increased `ApplicationVersion` to `18` without changing the package ID.
- Preserved the v1 backup schema and existing cats, photos, sightings, XP, quests, cover images, local-storage paths and restore logic.
- Updated browser offline cache key to `whisker-hunt-shell-v18`.

### Verification

- Browser tests passed: `test_browser.py`, `test_v05.py`–`test_v18_live.py` (15 suites total), including a real browser `MediaStream` generated by an animated canvas, pointer-drag capture, rolling-buffer bounds, camera shutdown, retake cancellation, fallback, and CatDex save.
- Real IndexedDB integration tests could not run: this environment blocks browser navigation to localhost and test origins (`ERR_BLOCKED_BY_ADMINISTRATOR`).
- **No Android APK was compiled** (no .NET Android SDK in this environment). Verify live WebView camera permissions, video playback, and touch gestures on a physical Android device. The native camera fallback should remain available if WebView live capture is unsupported.

### Limitations

- Cat location is **user-selected** by tapping the preview; no cat detector, identity recognition or AI-generated cat replica is claimed.
- Best-frame scoring estimates whole-frame clarity and exposure; it does not measure the cat's face, pose or sharpness specifically.
- The live camera depends on a secure browser context and Android WebView support; some Android WebViews may deny local camera streams. Use the native camera fallback if so.
